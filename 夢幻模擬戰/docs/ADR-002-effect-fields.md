# ADR-002：技能效果拆成結構化欄位

- **狀態**：已通過
- **日期**：2026-10-14
- **決策者**：學長 + CanL

---

## 背景

合併檢視 `merged/` 只把技能的外殼做成欄位：冷卻 `cooldown`、射程 `range`、範圍 `area`、`cost`、`category`。傷害倍率、強化／弱化的數值、持續回合、層數、封頂、能不能驅散，都只寫在文字欄。

每次要問「強化數值的上下限」「最高倍率是哪顆」「10 回合冷卻有哪些」，都得對文字重下一次正規表示式，而且會撈錯。2026-10-14 實案：用文字判斷單體還是範圍，把物理範圍的最大倍率寫成 1.7；用 `area` 欄算其實是 0.6（閃煌）。

## 決策

1. 新工具 `tools/parse_effects.py` 把五種來源的技能文字拆成欄位，產出 `merged/effects.json`，一段文字一筆。
2. 接在 `build_merged.py` 最後跑（`merged/` 每次會整個重寫，效果欄位要跟著重產）。只改了解析規則時可以單獨跑 `parse_effects.py`。
3. 規則沿用 2026-10-14 研究喵的技能規則統計（`analyze.py` 的關鍵字與時機分類，經過三輪人工抽查修正），搬進 repo、不引用暫存目錄。分類名去掉括號裡的說明（「屬性提升（攻智防魔技生命）」→「屬性提升」）。
4. 人工對照組 `tools/effects_golden.json`（43 筆）加 `tools/test_parse_effects.py` 逐欄比對；改規則後要跑，不一致就 exit 1。
5. 解析不了的句子原樣放 `unparsed`，不硬塞進某一類湊覆蓋率。

## 來源與取用順序

| kind | 來源 | 文字取哪個 | 筆數（2026-10-14） |
|---|---|---|---|
| 技能 | `merged/skills.json` | 遊戲畫面的 `text`，沒有才取 `wiki.description`；同名技能在不同英雄身上寫的不一樣（`variants`）時每一版一筆，`id` 加 `#2`、`#3` | 918（ingame 741、wiki 177） |
| 天賦 | 合併英雄檔的 `talent` | 遊戲畫面版 | 214 |
| 鑄紋技能 | 合併英雄檔的 `rune_skill` ＋ `sources/ingame/rune_skills.json` | 照（英雄, 技能名）去重；已解鎖的讀遊戲畫面，可獲得未解鎖的用 `text_wiki`，沒有遊戲畫面英雄檔的用 wiki 英雄頁的 `description` | 137（ingame 52、wiki 85） |
| 專屬裝備 | `merged/exclusive_gear.json` | `skill.text` | 164 |
| 士兵 | `sources/wiki/data/soldiers.json` | `skillDescription`（只有 wiki） | 154 |

遊戲畫面版跟 wiki 版衝突時取遊戲畫面版（CONTEXT.md 的規則）；每筆的 `text_from` 寫是哪一邊。

## 欄位定義

### 每一筆

| 欄位 | 說明 |
|---|---|
| `id` | 「kind:名字」，例：`技能:黯滅`、`專屬裝備:1UP`。變體加 `#N` |
| `kind`、`name`、`heroes`、`text`、`text_from` | 來源種類、名字、誰有（士兵是可帶的英雄）、原文、ingame 或 wiki |
| `category`、`cost`、`cooldown`、`range`、`area` | 只有技能有，直接帶合併檢視的值。遊戲畫面的冷卻欄空、wiki 有 `cd` 字串的解析成數字並標 `cooldown_from: "wiki"`；只有 wiki 的技能外殼全取 wiki（`type`→category、`cd`→cooldown、`span`→area），各標 `*_from: "wiki"`。0 表示寫「無」 |
| `variant` | 同名技能有幾版、這是第幾版 |
| `skill_name`、`gear_stat` | 專屬裝備：裝備上的技能名；開頭那句「生命+2%」是裝備本身隨強化等級走的能力加成，放 `gear_stat`，不算效果 |
| `soldier_type` | 士兵的兵種 |
| `damage` | 傷害倍率陣列，見下 |
| `effects` | 效果陣列，見下 |
| `unparsed` | 沒有任何效果或傷害倍率落在裡面的句子，原文照抄 |

### `damage`（「造成 X 倍（範圍／物理／魔法／戰鬥）傷害」）

| 欄位 | 說明 |
|---|---|
| `multiplier` | 倍率 |
| `dtype` | 物理／魔法；文字寫了用文字（`dtype_from: text`），沒寫且在傷害技能的主動段用分類欄（`dtype_from: category`），都沒有是 null |
| `scope` | 單體／範圍。**分類為物理傷害、魔法傷害的技能，主動段一律看 `area` 欄**：單體、自身是單體，其餘（直線、N格、N圈、全場）是範圍，`scope_from: area`。其他情況（天賦、鑄紋、裝備、士兵、技能的 `[被動]` 段、支援／主動類技能、area 欄空）才看文字，`scope_from: text` |
| `hits` | 「造成 2 次 0.5 倍」的次數，有寫才有 |
| `segment`、`raw` | 在主動段還是被動段；原文片段 |

主動段／被動段：技能文字用 `[被動]`、`[指揮]` 開頭的段是被動段，`[物理傷害]`、`[支援]`、`[主動]`… 開頭的是主動段；沒有標籤的照分類欄（分類是被動就是被動段）。

### `effects`

| 欄位 | 說明 |
|---|---|
| `polarity` | buff（對持有者有利）、debuff（有害）、neutral（施放者自己吃的代價、召喚物的屬性定義） |
| `type` | 見下表 |
| `stat` | 哪個屬性；多個並列用「、」接（「攻擊、防禦」）。免疫寫免疫什麼、驅散寫驅散強化或弱化、無視寫無視什麼、兵種特效寫兵種 |
| `value`、`unit` | 單次給的數值；單位 %、倍、格、回合、層、個、點（沒有 % 的定值） |
| `base` | 回血、護盾、固定傷害、持續傷害、吸血、反彈才填：「目標最大生命」「目標剩餘生命」「施放者智力」「施加者攻擊」「造成傷害」…（目標＝承受這個效果的部隊） |
| `duration` | 這個效果後面第一個「持續 N 回合」（同一句、不跨「。；」，引號裡的狀態定義算一句）；沒有再看前面的「N 回合的」。回血、驅散、再動這類一次性的不掛。狀態裡「觸發才施加」的隨機弱化等，引號外的回合數是狀態的，不掛 |
| `permanent` | true＝被動來源（天賦、鑄紋、裝備、士兵、技能被動段）裡沒寫持續回合、沒寫時機、不在引號狀態裡、不是一次性效果。是字面定義，「觸發一次後一直有效」的也會判 true |
| `stack_max` | 「可累積，最多 N 層／個」 |
| `cap`、`cap_unit` | 「（最多提升 N%）」「最高不超過…」這類封頂，掛在前面最近一個有數值的效果上，**跟單次的 `value` 分開**；「機率最高提升至 N%」不算 |
| `per` | 「每移動1格」「自身每有1個強化效果」這類線性加成的計數條件，原文片段；有 per 時 `value` 是每一單位的增量 |
| `dispellable`、`immunable` | 文字寫了「不可驅散」「無法被驅散」才填 false、「無法免疫」才填 false；沒寫是 null，不猜預設。「本技能施加的所有效果均…」管整筆的狀態型效果；「無法免疫的[固定傷害]」只管後面那一個 |
| `timing` | 觸發時機陣列，沿用研究喵的時機分類（戰鬥前、戰鬥中、戰鬥後、主動攻擊方、被攻擊方、行動結束時、回合開始時、回合結束時、戰場開場、使用技能時或後、攻擊前、受到傷害後、擊殺敵軍時、死亡時、遭受致命傷害時、移動距離、獲得或遭受強化／弱化時、被治療時）。「[被動]」的被不算被攻擊方，「交戰時」算戰鬥中 |
| `target`、`target_from` | 自身、單個敵軍、範圍敵軍、全場敵軍、敵軍、單個友軍、範圍友軍、全場友軍、友軍、召喚物。`target_from`：text＝文字有對象詞、area＝照技能的 area 推、default＝都沒有時的預設（增益給自己、弱化給敵軍） |
| `condition` | 生命門檻、兵種、地形、「若…」「…時」、觸發冷卻與次數限制的括號，原文片段陣列 |
| `chance` | 「N% 機率」 |
| `segment` | 技能的主動段或被動段（非技能是 null） |
| `raw`、`raw_of` | 效果本身的原文片段；`raw_of` 是其他欄位各自取自哪段原文（duration、cap、timing、condition…）。全部是 `text` 的子字串 |

### `type` 一覽

| polarity | type |
|---|---|
| buff（數值型） | 屬性提升、增傷、減傷、暴擊提升、防暴擊、治療效果提升、受治療提升、冷卻縮短、移動力／射程提升、回血、吸血、護盾、反彈傷害 |
| buff（關鍵字） | 免疫、不死、再動、先攻、護衛、無視、隨機強化、超絕強化、強化回合不減、兵種特效、驅散（驅散自己人的弱化） |
| debuff（數值型） | 屬性降低、降傷、易傷、暴擊降低、受暴擊提升、治療效果降低、受治療降低、冷卻增加、移動力／射程降低、固定傷害、持續傷害 |
| debuff（關鍵字） | 沉默、定身、眩暈、禁療、禁強化、禁護衛、無法反擊、偷取強化、強力弱化、隨機弱化、嘲諷、被動失效、驅散（驅散敵軍的強化） |

「遭受／受到」開頭的方向反轉：遭受傷害降低是減傷、遭受傷害提升是易傷、遭受暴擊率降低是防暴擊。

## 什麼不解析（留在 unparsed 或只留在 text）

- 具名狀態沒寫內容的：「施加[詭毒]」「獲得[格擋]」——不知道是什麼效果，不猜。
- 位移、傳送、召喚、技能替換、地形效果、「視為魔法傷害」、無視 COST、移動方式改變。
- 「防具失效」「武器技能失效」「禁止再動」這類不在上表的效果。
- 數值隨場上狀況變的：「減少的數值為命中的敵軍數量」「血量越高傷害越高」。
- 扣自己生命、損失剩餘生命這類代價句。

## 已知限制

1. **覆蓋率以句子算**：一句裡只要有一個效果被解析到就算覆蓋，同一句裡沒解析到的其他效果不會出現在 `unparsed`（例：決斷之刃的「[衰竭]無法觸發抵擋致命傷害」）。全庫句子覆蓋率 77.7%（2,663／3,426 句；只算效果本身、傷害倍率、裝備能力加成的原文片段，回合數與註記不算），專屬裝備最低（62.9%）。
2. **對象、時機、條件是規則推的**：對照組 43 筆逐欄全對，但規則是對著對照組調的。對照組以外兩次抽查（各約 26 筆效果），一筆效果每一欄都對的分別約 78%、73%，錯的集中在 `target`（狀態定義裡「自身」指誰、「其他友軍」是從哪邊說的）、`condition`（括號註記、跨句條件）、`timing`（前一句的時機被帶進來）。抽查到的錯有一部分之後修了，沒有再抽一次。
3. `permanent` 是字面定義，不代表遊戲裡真的整場有效。
4. 一句裡多個效果共用同一個「持續 N 回合」時全部掛上；狀態裡觸發才施加的例外（見 duration）。條件、時機、每 X 會沿用同一串（沒隔「。；」）前一個效果的。
5. 支援、主動類技能的傷害倍率不看 `area`（那是位移或增益的範圍，例：鏈鎖移動的 area 是 1格、傷害打單個目標），改看文字。這條是判斷，若要嚴格「有 area 就看 area」，物理範圍的最大倍率會變成鏈鎖移動的 1.5。
6. wiki 的天賦（沒有遊戲畫面英雄檔的 51 隻，`talents` 把每個星數的版本接在一起）沒有納入；wiki 的 `enchant-skills.json` 也沒有納入（鑄紋以英雄檔與 rune_skills.json 為準）。

## 驗證

```bash
python 夢幻模擬戰/tools/build_merged.py          # 產出 merged/ 與 merged/effects.json，印覆蓋率
python 夢幻模擬戰/tools/test_parse_effects.py    # 對照組逐欄命中率，不一致 exit 1；-v 印每一處
```

對照組選取：技能 19、天賦 6、鑄紋技能 6、專屬裝備 6、士兵 6；已知誤判句型（[被動]、無法免疫、最多提升、可累積最多 N 層、使用此技能後強化回合數不會減少、自身每有1個強化效果、戰前驅散敵軍5個強化效果）與兩端值（神氣合一冷卻 10、豪賭的計略冷卻 15、黯滅 1.8 倍、閃煌物理範圍 0.6、破滅之矛魔法單體 1.1、決斷之刃、御陣、魅惑）全部在內。
